## 2025-02-18 - Keyboard Accessibility for Custom Div Buttons
**Learning:** In Next.js/React applications, when replacing native `<button>` elements with `<div>` elements for complex styling (like flip cards), keyboard accessibility is completely lost. Screen readers don't recognize it as interactive, and keyboard users cannot navigate to it or trigger it using Enter/Space keys. Adding `tabIndex={0}` and a `focus-visible` ring is necessary but insufficient; an `onKeyDown` handler must be implemented to explicitly capture Enter and Spacebar presses (including `e.preventDefault()` for Space to prevent page scrolling) to achieve parity with native button behavior.
**Action:** Always ensure any interactive non-native element (`div`, `span`) has `role="button"`, `tabIndex={0}`, an `onKeyDown` handler mapping Enter/Space to the click action, and appropriate `aria-*` attributes (like `aria-expanded` for toggles). Always use Tailwind `focus-visible:` classes to provide clear visual focus rings for keyboard users.
